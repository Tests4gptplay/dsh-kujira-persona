## 用户需求与边界

- 参考 `QCYTSN/dsh-dafeiyu` 的桌宠体验及设置，但服务于 Kujira 的模型联动人物。
- **始终只有一只桌宠**；DSH 选择不同模型时，同一只桌宠换形象。同家族版本延续同一人物，不按模型或会话堆多个宠物。
- 桌宠可选、默认关闭，在插件自己的 UI 提供开关和设置；关闭桌宠不影响原有人设与世界观功能。
- DeepSeek 等按量接入优先展示对应余额/费用；走已接入的 Codex 账户时显示套餐余量。判断依据是实际接入和模型，而不是看到 GPT 名字就把 API 接入当成套餐。
- 用户允许在隔离验证中使用假设性的余额、额度与推理回复；模拟值只能留在测试侧，不作为真实账户数据或运行默认值。
- 先在临时区验证安装、设置、单宠切换、任务状态、费用/额度与关闭行为，修复问题后再交付试用。测试、验证、故障注入和发布辅助代码不进入产品主线/安装包。
- 保留此前的人设要求：world 是公共印象与关系，persona 是个人性格与记忆；可通过 DSH 对话扩充；用户选择优先；默认自称 DeepSeek/GPT/GLM 等模型名，不自称 XX娘，不机械播报内部步骤。
- 当前用户只是要求保存与记录，**不要继续长测试、发布或市场投稿**。恢复开发须以用户后续指令为准。

## 已有实现（不等于全部验收）

- `pet/client.js`：插件设置 UI、页面内单只桌宠、接入 DSH 模型选择、拖动与展示设置。
- `pet/controller.js`、`pet/model.js`：单一展示状态、模型/人物解析、任务状态和额度展示数据；关闭时取消用量刷新，不修改聊天推理逻辑。
- `pet/usage.js`：DeepSeek 余额路径和复用 Codex Native `codex-native/quota` 的只读套餐路径。现有 Codex 分支只显式处理 `codex-local`，其他账户适配器的覆盖仍需核对。
- `pet/index.js`：服务端桥接、设置持久化和事件更新；`pet/native.js`：Windows 单进程窗口桥接。
- `pet/assets/`：14 家族与 unknown 共 15 套 SVG/PNG 草图。它们是程序绘制的矢量草图及转换图，**不是图像生成模型的成品**，美术还没有得到用户验收；不要冒称用户要求的形象制作已全部完成。
- Windows C# 显示 helper 已能编译；已尝试处理 UTF-8 标准流、不抢焦点以及快速关开等待旧进程退出。但窗口可见性/生命周期验证仍失败，不能视为可用桌面版。
- 旧的 `index.js` 增加可选 pet 挂接，包声明新增 client 和桌宠资源导出；人物存储与模型目录模块沿用原有基础。
