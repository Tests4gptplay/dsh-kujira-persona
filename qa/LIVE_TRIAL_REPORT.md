## 模型端的边界

这次是**真实 DSH 应用＋当前 ChatGPT 助手人工中转模型输出**。本地 QA HTTP 服务接收 DSH 的真实 OpenAI-compatible 请求，助手读取这些请求后，将回复或工具调用写入临时 QA 回复文件，再由服务以 SSE 返回 DSH。工具执行、后续提示词、文件保存和界面完成状态由 DSH 自己产生。

菜单里的 `deepseek-chat`、`gpt-4o`、`gpt-4.1`、`private-model-v1` 都明确标有 `[TEST RELAY]`。它们是分类/切换试用的路由名称，不是实际访问这些品牌的推理服务。没有使用真实模型账号/API Key，也没有把当前 ChatGPT 网页会话暴露成自动 API。

因此本次可验证应用链路，但**不能证明真实 DeepSeek/GPT 在无人引导时每次都选对工具、自然遵循人设或正确处理所有输入**。回复文案由本助手根据实际请求编写；它们不是独立、盲测的模型行为样本。延迟包含人工中转、GitHub 读写与检查耗时；`Usage 0 tok` 也不是推理费用/速度测量。

## 发现的体验问题

插件说明确实可见，但同一长段落同时出现在包说明与组件说明中，页面显得重复。此项是可收短的文案/显示体验，不是本次发现的卡死或存储失效；本次未改发行包。

## 测试搭建中遇到的情况

1. ChatGPT 临时容器执行接口报 ClientError，未能在那里启动应用；随后转到独立 GitHub Runner 完成真实网页试用。
2. 第一次远端启动使用了这个已发布 CLI 不接受的位置参数 `--patch`，启动失败。改用隔离 profile 的实际 `cordis.patch.yml` 后成功。仅修正 QA 驱动，没有修改 DSH/Kujira 生产代码。
3. 初始临时工作区位于 QA 仓库下，DSH 的变更展示把上级 QA 文件也列入。为临时工作区独立 `git init` 后，后续场景不再受上级仓库文件影响。这不代表插件改了那些证据文件。
4. 一个外部编辑的测试命令字符串因换行转义产生语法错误；它没有执行。改成简单文本后同场景成功。失败命令 `0014` 与成功重试 `0015` 均保留，未伪装成全程零错误。
