## 1. 业务目标与用户价值

让用户在 DSH 日常对话中自然地与有辨识度的 AI 角色交流：切换模型家族时更换人物，人物认识彼此，又有各自的性格和记忆。用户通过聊天补充世界观、改变人物、创建自定义角色并安排模型对应关系，无需先学习配置文件。

桌宠是可关闭的陪伴层，不是人设功能的前置条件。只有一只，跟随当前前台对话的模型；它用真正的动作与气泡表达思考、工作、等待、完成等状态，并展示宿主已有的工作统计及实际接入允许查询的账户信息。不能让陪伴功能反过来拖慢或阻断 DSH。

AI-gijinka 是持久的研究和创作参考库：把已有角色的形象、来源、称呼、梗、基本互动与缺项放在一起，让后续通常先查库，仅为具体新增或争议内容回访外站。

当前目标是可实际使用、人物正确、动画自然、修改可落盘的同人娱乐功能，不是堆叠复杂的世界观宪法或运行防御组件。没有建立下载量或付费用户的业务目标；下载次数不能直接解释为独立用户数。

## 3. 必须保持的产品约定

### 人物与共同世界

- world：共同称呼、外界印象、梗和少量跨作品互动，帮助当前人物认出其他角色。不预设学院、公寓或固定家庭。
- persona：角色自己的个性、偏好、表达和独立记忆。外界印象不等于角色每次都必须照做。
- 同模型家族不同版本、不同推理档位默认延续同一人物；以实际 provider/model ID 判断，不拿显示名或 API 协议猜身份。
- 用户明确指定的角色、名字、绑定与设定高于插件预设。不得用更新覆盖已经养成的内容。
- 默认自称 GPT、DeepSeek、GLM 等模型家族名称或自然说“我”，不主动自称“白龙娘”“XX娘”。形象与别称仍保留，用户另有喜好则按用户选择。
- 扩充世界观、修改人物、自定义角色和模型绑定通过 DSH 对话完成。保存后自然接话，不机械播报插件步骤，不把口头承诺当成实际写入。
- 主要面向用户的对话，不扩展子代理性格管理。

### 说明与运行负担

GitHub 首页 README 可以详细；安装后的插件介绍只讲必要使用信息。给 AI 加载的 `instructions/README.md` 要简洁，只保留必要编辑入口、保存/刷新语义和用户优先原则，不堆实现细节。

公开 README、详情页、示例和版本说明使用通用功能描述，延续现有文案口径，遵循 `V2_CHARACTER_NOTES.md`。不要在交接或发布时把已经整理过的说明恢复成冗长人物清单。

保留按需读取和缓存。插件编辑成功后更新相应快照；外部工具修改文件后按原有工具做一次对应 reload，不依赖周期扫描或要求用户反复重启。测试驱动、假数据、故障注入、截图程序及发布辅助脚本留在 QA/临时区，不进入产品运行包；不为本次功能添加额外模型调用、自检循环或无关校验链。

### 桌宠与数据显示

桌宠默认关闭；切模型替换同一只，而不是每模型/会话新开窗口。后台任务不能抢走前台人物。页面内和 Windows 原生显示共用状态，关闭桌宠不影响人设。

用户已明确：桌宠代码与实现可参考或复用 `QCYTSN/dsh-dafeiyu` 的合适部分，实际复用时保留其 MIT 版权和许可；角色美术则依据已确认的人物参考自行制作，不搬用该项目的成品帧图，不做换色换皮，也不继续沿用被否决的同脸模板。技术复用与自行制作美术分开推进；本轮尚未移植参考项目代码或生成素材。

按实际接入区分余额和套餐：DeepSeek API Key 与 DeepSeek 登录账户分别处理，现有代码对 Codex Native 的明确入口是 `codex-local`。普通 GPT API 不是套餐；其他账户适配器是否支持需核实，不凭名称复用另一接入的余额。

轮次、步骤、生成速度、累计 Token、缓存命中和上下文占用复用 DSH 统计；上下文百分比不是任务完成率，也不是套餐剩余。没有数据时明确省略/显示未提供，不能塞入模拟默认值。
