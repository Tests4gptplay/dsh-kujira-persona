# Kujira v2 开发检查点 — 2026-10-24

本分支是开发候选，尚未发布。以下内容依据本轮实际代码、运行记录与图集检查更新，不把待完成的素材规划计为成果。

## 已实现的功能

- Web 与 Windows 共用逐帧播放器。普通动作之间有约 100 ms 的透明过渡；单帧支持原图裁切、目标位置与目标尺寸。拖起、落地、点触、随机待机动作和减少动态均按实际素材工作。
- 待机、思考、查找、编辑、执行、检查、等待、完成和出错有对应的功能状态。工具的暂时失败只触发短暂反应；任务终止失败停在错误动作末帧。并发工具及批准请求分别跟踪。
- 前台会话持有桌宠展示状态；其他会话与后台子代理不接管它。切换会话会重置动画播放状态，复用同角色已加载的素材。
- 连接重建后，浏览器可以接纳服务重新开始的状态版本并恢复前台选择；旧连接返回的请求结果不会覆盖新的连接状态。
- 通用 manifest 构建器使用实际存在的帧补齐功能状态。缺少专属素材时，思考与工作细分可复用通用工作帧，等待与结果可复用中性帧；来源写入 `fallbackSources`。这些复用不计为独立绘制的动作。
- 桌宠保持默认关闭，人设、世界观及对话修改功能独立可用。安装包白名单收录运行代码、角色素材、Windows EXE 和许可，开发 QA 脚本保留在源码仓库。

## 候选美术状态

新动画图集以本轮角色参考及 AI-gijinka 资料库为范围。GPT 已接入任务动作、触摸反应、拖放与待机小动作；其他角色依各自造型生成和接入。未明确性格的角色先采用中性的阅读、工作、等待和结果反应。

本检查点已接入全部 14 个公开角色。GPT 有 16 个动作片段；DeepSeek 有 8 个，包含修订后的待机／思考比例及拖起／落地。MiMo 当前采用 7 个独立源姿态：待机眨眼与工作姿态组成多帧播放，等待复用待机，完成和出错分别保持单张姿态。其他角色采用已有工作、等待和结果动作，功能阶段仍可复用。

切帧根据生成原图的实际布局测量，存在贴边、低透明度桥接或不完整主体时分别标记、调整选帧或排除；生成提示中的格数不作为实际帧数。最终 manifest 的图像文件、源选区和显示画布边界检查已通过。坐标数据保存在 `pet/art-layouts.json`，可用 `scripts/qa/build-secondary-art.mjs` 重建。所有新图仍属于候选美术；上述检查不代替最终美术验收。

标准状态复用与专属连续帧分别记录。功能可运行、图集几何可裁切、正常桌宠尺寸下可观看和最终美术接受，是不同的检查项目。

## 可复现入口

- `scripts/qa/routing-check.mjs`：模型选择优先级、用户自定义绑定和中性状态降级检查。
- `scripts/qa/verify-native.ps1` 与 `native-protocol-check.cs`：读取当前仓库源码和 GPT 图集，使用已有 Windows .NET x64 编译器，在新隔离目录编译和验证；不会回写产品 EXE 或用户配置。
- `scripts/qa/build-playable.mjs`：内嵌当前播放器和 `ART`，复制实际引用的 PNG，生成不依赖服务器、npm 或网络的 HTML 试玩。
- `scripts/qa/playable-check.mjs`：通过 Chromium 验证离线试玩；结果与浅色、深色、手机宽度截图写入试玩的 `qa` 子目录。
- `scripts/qa/manifest-check.mjs`：检查实际 PNG 尺寸、源选区、显示画布边界、资源引用及功能状态解析；不会修改图像。

验证摘要保留必要的源码与产物散列及检查结果。账户信息、临时认证、完整模型请求、私有运行日志和主机维护材料不进入公开交付。
